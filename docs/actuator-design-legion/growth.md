# Capability and growth

## Current state

The content pack defines six professional responsibilities, routing signals, deliverables, evaluation prompts, and a shared palette. This directory adds six source-linked methods, representative cases, an acceptance vocabulary, and a source-hash index. Agents can use these files when a task explicitly asks them to read them and provides access.

The source-preview-v0.1.0-beta.2 preview pairs application source version 0.1.0-beta.2 with content pack version 1.0.0. Crew selection requires a source build containing the beta app-version compatibility fix. Existing beta.1 installers lack the fix and may import a pack successfully but fail to select it. This preview supplies source and content assets, with no new desktop installer or direct installer upgrade.

Current capability is input review, evidence organization, planning, and scoped interpretation of saved records. The pack does not automatically inject this knowledge, install executable Skills, create specialist runtime sessions, or bind SOLIDWORKS tools. A declared capability level or tool name does not prove measured execution capability.

The source audit reviewed saved records and original method notes. CAD execution, fresh native reopen, new STEP export/re-import, licensed transmission-software execution, and physical life/NVH validation were not run in this audit.

## Single next priority: knowledge/Skill execution binding

Bind explicit knowledge retrieval and a project-scoped Skill to a real execution adapter. The binding must make the selected agent's source references, actual tool availability, permission scope, and output evidence observable. SOLIDWORKS remains a later execution integration rather than a capability supplied by this pack.

The binding is reviewable when a bounded task demonstrates all of the following:

1. The chosen role retrieves the intended file/version and exposes the sourceIds it used.
2. The runtime discovers actual tools and permissions; persona declarations do not create either.
3. A planning-only task reads knowledge and produces an input/check plan without starting CAD.
4. A separately authorized execution task has a single CAD writer, writes to its designated project/output scope, and returns versioned evidence.
5. Failure, interruption, missing tool, and stale evidence remain visible; no status silently changes to passed.

Until that binding exists, improve results through explicit task context and source-backed review, not by raising profile levels.

## Promote experience with evidence

A new observation starts as a project case. Preserve its trigger, failed version, repair, criterion, result, and applicability. Only generalize it after a scoped rerun supports the repair and an independent check or additional project establishes the claimed range. Keep contradictory cases and unresolved items.

Promotion changes a method only within demonstrated bounds. It does not turn a kinematic example into strength/life approval, discrete clearance into continuous clearance, or a readable STEP into manufacturing release.
