# 舰长主舞台与完整皮肤精致化设计

日期：2026-08-30
状态：四部分设计已逐项批准，等待书面规格复核
范围：星潮航局桌面端 UI 精致化，不包含发布

## 1. 背景与结论

现有实现已经具备清单驱动皮肤、十支舰队、全局 `CaptainHost`、分层舰长渲染、八状态编排、语音策略和视觉回归能力，但实际界面仍然粗糙。根因不是缺少底层能力，而是组合关系错误：`CaptainHost` 以固定定位的独立卡片覆盖在页面右侧，主内容仅通过保留内边距避让它。舰长因此仍像外挂组件；场景、人物和工作区也没有形成一个统一画面。

本设计采用已经批准的组合方向：

- A“舰长主舞台”作为舰队港口、新对话、空白聊天和航海图的主工作台。
- B“双层指挥舱”作为活跃聊天、任务、项目、技能和连接等高密度页面的布局语言。
- C“电影式沉浸”只用于欢迎页和待机模式，不侵入正常工作流。

Alice 仅作为“角色先建立情感存在、界面再承载功能”的设计参考。本项目不复制其视觉资产、代码、文案或品牌表达。

本规格是对 `2026-08-23-adaptive-captain-fleet-skins-design.md` 的视觉质量深化。原有皮肤运行时、安全边界、状态机、语音策略和 Live2D 适配接口继续有效；冲突之处以本规格的构图、资产与验收要求为准。

## 2. 目标

1. 将舰长从右上角浮动卡片升级为工作区的全局视觉主体。
2. 让场景、舰长、工作面板和导航形成统一光色与空间层级。
3. 保持功能位置稳定，同时让十支舰队在隐藏名称后仍可明显区分。
4. 将“精致”转化为可验证的资产、构图、性能、可访问性和实机验收标准。
5. 复用现有运行时和状态编排，不复制十套页面，不建立第二套主题事实来源。

## 3. 非目标

- 不制作或宣称正式 Live2D/Cubism 模型。
- 不开放第三方皮肤插件、远程皮肤下载或任意 CSS/HTML/脚本扩展。
- 不重新设计任务领域模型、Agent 内核或舰队职责。
- 不默认开启语音、麦克风或持续环境监听。
- 不以本设计批准为安装包发布、GitHub Release 或公开推广授权。
- 不追求对 Alice 或其他产品的像素级复刻。

## 4. 总体布局架构

### 4.1 三种内容密度

全局 Shell 只暴露三种布局意图：

- `stage`：场景化主舞台。适用于舰队港口、航海图、新对话和空白聊天。
- `deck`：高密度指挥舱。适用于活跃聊天、任务、项目、技能和连接。
- `compact`：紧凑入口。适用于设置、模态界面、小窗口或空间不足场景。

页面只声明内容密度，不直接判断舰队 ID，也不直接设置舰长尺寸、坐标、服装或动效。

### 4.2 `CaptainStageLayout`

新增一个 Shell 级组合边界 `CaptainStageLayout`。它负责把导航之外的工作区组织为：

1. 场景平面：舰队远景、中景、环境光、可读性遮罩与前景装饰。
2. 内容平面：目标输入、任务摘要、对话和页面业务内容。
3. 舰长平面：舰长人物、字幕、状态反馈和明确交互控件。

`CaptainAppShellSurface` 继续作为全局接缝，但从“舰长与内容并列挂载”调整为“事件桥接器 + `CaptainStageLayout` + 单一 `CaptainHost`”。`CaptainHost` 仍只挂载一次，跨路由保持状态连续性。

在 `stage` 模式中，舰长进入布局插槽，不再使用独立浮动卡片；在 `deck` 和 `compact` 模式中，可继续使用受控伴随层或紧凑入口。不得同时出现两个舰长实例。

### 4.3 主舞台构图

- 左侧导航保持现有稳定位置，不随舰队改变信息架构。
- 内容区采用半透明“指挥台”，承载主要目标、任务摘要和输入操作。
- 舰长占可用工作区宽度的 34%–40%，最小 360 像素、最大 560 像素。
- 舰长身体可以进入背景和内容之间，但脸部、字幕和主要操作必须位于各自安全区。
- 场景右侧为人物视觉焦点，左中部为文字和交互焦点；两者通过环境光和材质统一，而不是两个独立卡片。

### 4.4 双层指挥舱

- 中央区域优先保证对话、任务看板、项目文件和工具结果的可读面积。
- 舰长在宽度不低于 1180 像素时占右侧 240–300 像素伴随层。
- 伴随层降低粒子和视差强度，只保留状态、字幕和关键控制。
- 舰长身体默认不接收指针事件，只有语音、静音、展开、重试等明确控件可交互。

### 4.5 电影式欢迎与待机

- 允许舰长占据 45%–55% 的画面，并使用更强的环境叙事。
- 任务面板按需浮现，但必须保留明确的“开始航程”入口。
- 一旦用户进入活跃工作流，立即切换到 `stage` 或 `deck`，避免持续占用任务空间。

## 5. 皮肤清单深化

现有 `FleetSkinManifest` 增加版本化的构图契约，至少包含：

- `composition.stage`：舰长宽度、人物焦点、场景焦点、内容安全区、字幕安全区。
- `composition.deck`：伴随层宽度、人物裁切、内容保留宽度和控件位置。
- `composition.compact`：头像焦点、静态图和展开锚点。
- `scene.layers`：远景、中景、前景、环境光和可读性遮罩的注册资产 ID。
- `materials`：导航、标题栏、指挥台、卡片、输入区、弹窗和浮层的材质令牌。
- `graphicLanguage`：圆角、边框、分隔纹样、选中态和装饰图形。
- `captain.presentation`：主舞台、伴随层、紧凑和静态降级构图。
- `motion.profile`：切换、状态反馈、视差和粒子规则，以及减少动效替代值。
- `audio.profile`：默认静音的关键事件提示和系统 TTS 参数。

所有资产仍必须通过构建时静态注册表引用。清单不得包含远程 URL、任意文件路径、CSS、HTML 或可执行代码。

## 6. 完整皮肤的七个层级

每支舰队必须同时改变以下七个层级。颜色变化只算其中一个视觉变量，不能单独构成完整皮肤。

1. 世界场景：独立远景、中景、前景、环境光和可读性遮罩。
2. 舰长呈现：统一角色身份，但更换服装、配件、姿态、构图和环境光。
3. 界面材质：侧栏、标题栏、卡片、输入区、弹窗和浮层。
4. 图形系统：边框、圆角、分隔纹样、选中态和装饰图形。
5. 字体语气：标题、正文、数字和标签的字体层级、字重与字距。
6. 动态气质：视差、粒子、呼吸、状态反馈和切换节奏。
7. 声画反馈：默认静音；显式启用后，关键提示和播报气质跟随舰队。

以下任一情况出现时，舰队不得标记为完整皮肤：纯渐变冒充场景、复用同一背景后调色、缺少舰长专属构图、低分辨率放大、明显重复纹理、无意义粒子或未完成桌面实机检查。

## 8. 舰长资产标准

每支舰队至少提供：

- 主舞台半身或大半身构图。
- 伴随层竖向构图。
- 紧凑头像和静态故障降级图。
- 基础人物、舰队服装、表情和前景光效的独立图层。
- `idle`、`listening`、`thinking`、`executing`、`reporting`、`warning`、`success`、`failure` 状态的可辨识反馈。

十套舰长必须保持相同的面部、发型、身体比例和角色辨识度，不能因皮肤变化看起来像十个不同角色。在 1024×640 至 2560×1440 范围内不得裁掉脸部、字幕或主要操作。

## 9. 舰长互动与数据流

系统保持单向数据流：

`页面与任务事件 → CaptainOrchestrator → CaptainSnapshot → CaptainHost → Renderer / 字幕 / 语音`

页面只能发送语义事件，例如 `input.focused`、`task.thinking`、`tool.started`、`permission.required`、`task.succeeded`、`task.failed`、`fleet.switching` 和 `fleet.activated`。页面不得直接命令舰长播放具体表情、动作或语音。

状态优先级为：

`failure / warning > permission.required > reporting > executing > thinking > listening > success > idle`

高优先级状态结束后恢复仍然有效的下一状态，而不是无条件回到 `idle`。

舰长点击区域只打开轻量控制面板，提供当前状态、手动朗读、静音、展开和收起。舰长不能代替用户确认权限、发送内容或执行高风险操作。

## 10. 语音策略

- 初始状态为静音，用户必须显式开启舰长语音。
- 字幕始终显示，并先于或同步于声音出现。
- 只自动播报欢迎、权限确认、重要风险和任务完成。
- 普通助手回复不自动全文朗读；用户可以手动要求朗读。
- 一键静音立即停止当前播报并清空等待队列。
- 语音输出与麦克风权限完全分离。
- 不朗读凭据、用户原始输入、私人文件内容或未经整理的工具输出。
- 首版继续使用系统 TTS；未来语音服务通过独立适配器和单独授权接入。

## 11. 原子换肤与错误处理

舰队切换继续采用事务式流程：解析并校验清单，预载必需资产，全部就绪后在同一次提交中更新场景、材质、舰长、动效和声音策略，成功后再持久化舰队选择。

- 必需资产失败：取消切换，旧皮肤完整保留。
- 可选粒子、环境声或次要纹理失败：关闭对应效果，功能继续可用。
- 分层渲染失败：切换到当前舰队的静态舰长图并显示可诊断状态。
- TTS 不可用：保留字幕并显示“语音不可用”，不得报告播报成功。
- 非法状态事件：丢弃事件并恢复最近有效状态。
- 持久化数据损坏：恢复望潮团并记录不含用户内容的诊断事件。

禁止先改颜色、后补背景或舰长的可见中间状态。

## 12. 性能边界

- 只加载当前舰队，并预取用户正在悬停或聚焦的下一支舰队。
- 必需资源就绪后的目标过渡时间为 250–450 毫秒。
- 本功能不得造成超过 100 毫秒的主线程长任务。
- 动态效果以稳定 60 FPS 为目标；性能不足时依次降低粒子、视差和环境动画，不牺牲输入响应。
- 应用失焦、窗口最小化或舰长不可见时暂停装饰动画。
- 位图最长边不超过 4096 像素，并按实际显示尺寸解码。
- Electron 试运行不得出现缺失资源、新增控制台错误或由本功能导致的持续内存上涨。

## 13. 可访问性

- 正文和交互文字达到 WCAG AA 对比度。
- 焦点轮廓和非文字控件对比度不低于 3:1。
- 所有舰长控件支持键盘操作并具有明确可访问名称。
- `prefers-reduced-motion` 下关闭呼吸、视差、粒子和装饰性转场，但保留清晰状态变化。
- 高对比度模式保留每支舰队的图形、字体和构图身份，不统一退化为黑白模板。
- 字幕不能覆盖脸部、输入框、确认、取消、错误恢复或窗口控制。

## 14. 测试策略

### 14.1 单元测试

- 皮肤清单和构图令牌完整性。
- 三种显示模式与窗口尺寸解析。
- 状态优先级、并发恢复和事件有效期。
- 语音默认关闭、显式启用、关键事件过滤和队列清理。
- 必需资源失败回滚与持久化恢复。

### 14.2 集成测试

- 十支舰队逐一切换，确认场景、组件、舰长、动效和声音策略同步提交。
- `stage`、`deck`、`compact` 跨路由切换时 `CaptainHost` 不重复挂载。
- 任务、工具、权限和语音事件驱动正确状态。
- 渲染与 TTS 故障触发预期降级，业务功能继续可用。

### 14.3 端到端测试

- 选择舰队、跨页面保持和重启恢复。
- 默认静音、显式开启、关键事件播报和一键静音。
- 必需资源失败时旧皮肤保持完整，失败选择不持久化。
- 键盘导航、减少动效和高对比度模式生效。

### 14.4 视觉回归

- 十支舰队 × `stage`、`deck`、`compact`：30 张。
- 十支舰队减少动效模式：10 张。
- 十支舰队高对比度模式：10 张。
- 最低自动视觉基线总数：50 张。
- 在 1024×640、1280×720、1440×900、1920×1080、2560×1440 五档窗口验证布局。

## 15. 人工视觉验收

自动截图一致不代表界面精致。每支舰队必须人工确认：

1. 舰长成为视觉主体，而不是右上角挂件。
2. 场景、舰长和工作面板的光色统一。
3. 页面信息层级能在三秒内理解。
4. 输入区与主要操作始终清晰。
5. 不存在低清素材、错误裁切、重复纹理或廉价粒子。
6. 隐藏名称后仍能辨认舰队视觉身份。
7. 换肤过程中不存在局部换色或混合皮肤帧。

视觉评审以本项目的原创视觉语言、桌面工作效率和本规格为准，不以复制参考网站作为验收方式。

## 16. 完成定义

只有同时满足以下条件，才能报告“精致化完整皮肤首版完成”：

1. 十支舰队全部通过清单、资产来源和七层完整性校验。
2. 十支舰队均具有独立场景、界面材质、图形语言和舰长呈现。
3. 三种布局模式、八种状态和语音策略符合本规格。
4. 最低 50 张视觉基线和五档窗口检查通过。
5. 单元、集成、端到端、构建和 Electron 实机试运行通过。
6. 人工视觉验收逐支舰队通过。
7. 不存在局部换肤、缺失资源、未授权素材或被错误描述为 Live2D 的效果。

任何一支舰队仍为渐变占位、复用调色背景、缺少舰长构图或未经实机检查，整个版本必须标记为未完成。

## 17. 实施边界与顺序

后续实施计划应拆为以下依赖顺序，允许分批提交，但不得分批宣称完整版本：

1. 构图契约、纯函数布局解析和失败测试。
2. `CaptainStageLayout` 与单一 `CaptainHost` 的 Shell 组合重构。
3. 一支舰队完成主舞台质量样板，用于验证构图与性能，不作为版本完成证据。
4. 十支舰队的原创场景、材质、图形和舰长资产批次制作。
5. 原子切换、语音、安全与可访问性回归。
6. 50 张视觉基线、五档窗口、构建和 Electron 实机验收。

实施不得顺带重构与视觉目标无关的 Agent 内核、项目模型或浏览器模块。
